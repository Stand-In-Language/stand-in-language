The Net That Counts Itself

Interaction nets, how Telomare runs on one, and how a graph whose every rewrite is local lets a compiler bound memory.

1Graphs that compute

An interaction net (Lafont, 1990) is a program that is literally a graph. Running it means rewriting the graph in place until nothing more can fire. (IC, as in --ic, stands for interaction combinators, a minimal family of interaction nets; section 3 covers them and how Telomare’s runtime differs.) Three rules define the whole game:

Every node — called an agent — has a fixed number of ports, and exactly one of them is the principal port. Every port is connected to exactly one other port by a wire; nothing dangles, nothing is shared. And a rewrite may happen only where two agents meet principal-to-principal — such a wire is an active pair (a redex). The rule for that pair of agent kinds deletes both agents and splices a small, fixed replacement graph into their neighbors’ wires.

Two consequences make the model worth the trouble. Rewrites are local and of known size: no environment lookup, no global search, so “what does one step cost in memory?” has an exact per-rule answer — this is what makes metering possible. And the model is confluent: the order in which you fire active pairs cannot change the result, only the route taken — this is what lets one of the two analyses ignore scheduling entirely.

2An agent, and a rule firing

Here is the rule that fires when a left projection meets the pair it projects. Both agents die; the pair’s left component is wired straight to wherever the result was going; the right component, now unused, is handed to an eraser ε that will consume it. Two agents are deleted, one is created, three wires move — and the runtime’s counters record exactly that.

In Telomare’s runtime (src/Telomare/IC.hs) the agent kinds are the ICKind type, and they fall into five families:

3Interaction combinators, and Telomare’s dialect

Interaction nets let you invent any agents and any rules. In a second paper, Interaction Combinators (1997), Lafont showed how few you actually need: three agents — the constructor γ, the duplicator δ and the eraser ε. γ and δ have a principal port and two auxiliary ports; ε has only its principal. One rule per pair of kinds gives six rules. Two alike agents annihilate (γγ, δδ): both vanish and their auxiliary wires join pairwise. Two unlike agents commute (γδ): each passes through the other, leaving a square of four agents, and this is how anything gets copied. The eraser erases whatever it meets (γ or δ vanishes and leaves an eraser on each auxiliary wire; two erasers simply vanish). Lafont proved this tiny system universal: every interaction net can be translated into it. This is what IC stands for — interaction combinators — in --ic and Telomare.IC.

Telomare’s runtime is not compiled down to these three agents. It keeps their structural rules — copying, taking apart, erasing — almost exactly, and adds agents of its own for everything specific to the language. The structural core, rule by rule, with the rule names from src/Telomare/IC.hs:

Where the dialect departs from pure combinators:

Polarity. Every Telomare agent is either a value (Zero, Pair, Ref, Gate, Abort, and the two poison values) or a consumer whose principal port points at the value it waits for (SetEnv, Apply, Scrut, Left, Right, Split, Dup, Era). Rules fire between a consumer and a value, plus duplicator meeting duplicator; in Lafont’s system any two agents can meet. The consequence is visible in the runtime: an eraser cannot meet a duplicator or an unfinished computation, so it waits at the computation’s output until a value arrives, then erases that. This is why the net fires both arms of a gate — the unselected arm runs to a value before its eraser can reach it.

Labels. A single δ cannot correctly copy a net that itself contains δs: the inner and outer duplicators would annihilate when they should pass through each other. Indexing duplicators by labels, so that only equal labels annihilate, is the “abstract algorithm” of sharing-graph reduction (Lamping’s algorithm without its bracket agents; the same device HVM uses). Without brackets, labels are only guaranteed correct for stratified programs — which is exactly what EAL certification (Telomare.EAL) establishes, and why it is the runtime’s correctness precondition.

Code is a table, not a net. In pure combinators a function is a net, and copying it means a δ commuting through its entire body. Telomare compiles every Defer body to a template, stored once, and represents that code in the live net as a one-port ICRef; a closure is a pair of such a pointer and its environment. Copying code copies the pointer (dup-leaf); applying it (apply-ref) splices a fresh copy of the template’s agents into the net. Apply-ref and the guided dup-closure shortcut are the rules whose result is not a small fixed graph: each is as large as the template or closure involved, though fixed for each.

Native control, errors and boundaries. Gate, Scrut and Abort choose code by a value’s shape; ICStuckV and ICAborted carry errors as values that flow through consumers and vanish when erased; ICRoot and ICExt mark the net’s free wires (the result, and a template’s boundary) and never interact. None of these has a combinator counterpart — pure combinators would have to encode them as nets. By Lafont’s universality theorem such a translation exists, but it would give up the code table and native branching that make this runtime practical. Telomare’s IC is best read as an interaction system in the combinators’ style: Lafont’s structural rules, with labels, plus a Telomare-specific alphabet.

4From Telomare to a net

Telomare compiles onto this model unusually cleanly because the language has no binders: Env is the only variable. Every Defer body becomes a static template — a frozen little net with a single environment wire in and a result wire out — plus an ICRef agent pointing at it. Copying a function is copying a one-port pointer; only when an ICApply reaches the ref does the template get instantiated, its nodes spliced into the live graph. Inside a body, the env wire fans out through an ICSplit tree shaped by which components the body actually uses; a component used twice gets an explicit ICDup, and the EAL analysis (Telomare.EAL) is what certifies that this duplication discipline is sound and guides how closures are copied.

5The machine’s memory: the node map

The entire living graph is one Haskell value: icNodes :: IntMap Node. Keys are agent ids — plain Ints from a counter. Each Node is a kind plus an inner map from its own port slots (slot 0 is principal) to the far end of each wire, a (node, slot) pair — so every wire is stored twice, once from each end. Beside it sits icActive, a LIFO worklist of agent-id pairs that might be active (a rewrite can consume a node another entry mentions, so stale entries get skipped at pop time).

So the units of the certificate are counts of fixed-size objects, not bytes: an agent is one map entry, a port entry one slot, a pending pair one worklist cell. Bytes are count × bytes-per-object for whatever implementation hosts the net — roughly 300 bytes for a three-port agent in the current Haskell representation (its entry in the node map, the node itself, its own port map and three port values), on the order of 8–16 in a compact C-style runtime. That is why the certificate calls the quantity logical storage and excludes GC, readback and process memory: it bounds the abstract machine’s population and lets you choose the multiplier.

6Why this graph can be bounded

Every rule creates and deletes map entries only at explicit account sites, so each of the three counters moves by a known constant per rule. The peak of the counters over a run is then a precise, meterable quantity (--ic --meter measures it) — and two analyses address it for every input at once: one bounds it, the other estimates it, as the end of this section explains.

The walk gives usable numbers. For tc_ultra_minimal:

agents         ≤ 36·|input| + 1130
port entries   ≤ 108·|input| + 2894
pending pairs  ≤ 36·|input| + 647
walk · holds for every finite input · feed it 100 cells, the net never exceeds 4,730 agents

The compositional figure exists even when the walk gives up, and it is where the astronomical numbers come from: a copy multiplier (1 + 3F)ᴸ — F duplication fans, L the EAL box-nesting depth — applied to the program’s own code, independent of input. That multiplier grows only single-exponentially in L, while elementary affine logic promises no better than a tower of exponentials of height L, so the figure is an estimate rather than a proven bound. For tic-tac-toe:

agents         ≤ 4.78×10¹¹·|input| + 1.57×10⁵³⁴
compositional estimate · measured peak of a real game: 265,483 agents

One last honesty device: figures over six digits are printed rounded up to three significant figures, so rounding never makes a printed figure smaller than the one the analysis computed. The certificate you get from --ic --certificate is the better of the two analyses, labeled with its method, and --ic --compile stores it in the artifact so a compiled program carries its own certificate.
